Plate B · What stays in your browser

The Labs OS record

Labs OS keeps a record of your visits so the labs can tell you where you left off. It stays in this browser.

What
An activity log (which lab page was opened, when it was left, how long it was visible, which controls were used, what a lab computed), each lab's saved progress, and your settings: the recording choice, the sharing choice and the time of your last visit.
Where
IndexedDB in this browser, in a database named labs. It is not a cookie and it does not travel with requests. A private window discards it when it closes. A window that blocks storage keeps it in memory until the tab closes.
How long
Until you delete it or clear this site's data. The log keeps its newest 5,000 events and a count of the ones it dropped.
Export
Labs hub, Your data, Export JSON: one file with every record.
Delete
Labs hub, Your data, Delete everything. Stop recording keeps later visits from being logged at all.

Some labs also keep their own settings in this browser's localStorage, for example a model key you entered or a plan you saved. Clearing this site's data in the browser removes them.

Plate C · What is sent, only if you allow it

Usage events

The labs ask once. Until you choose Allow, nothing on this plate is sent. No thanks is remembered and the question does not return. The basis is your consent, and you can withdraw it at any time.

  • Which lab you open, and from where: the page's path, and for a link you follow on the hub, the lab it leads to and whether the link sat on a card, in the side list or on the welcome plate.
  • How long the page was visible, and how long it was open.
  • Which kinds of controls you used: the name of a control or of a result, with counts and durations.
  • A random id for this browser, made when you allow sharing. It tells one browser's events from another's and is derived from nothing about you.
  • A random id for each page load, and the time of each event.
Never
Anything you type. A lab records which control was used, never what was typed into it. As a second guard, before an event leaves, its data is reduced to numbers, yes or no values and short plain labels: text longer than 64 characters, text of more than three words, text with other characters and anything nested inside are dropped. No name and no email address: the labs hold none. No IP address is stored with the events. The servers that receive a request see the address it comes from, as every web server does, and the events table has no column for it.
To whom
Supabase, a database host. The project runs in the EU (West EU, Paris). Only the owner of this site can read the events. A visitor's browser can add events and erase the events of its own id, and can read none.
Why
To see which labs are used and where they fail.
Events sent
Only events recorded after you chose Allow, and none while recording is off.
Plate D · How long it is kept

90 days raw, then daily counts

Raw events are kept for 90 days. Each night, every day older than that is reduced to counts (events, browsers and page loads, per lab and per kind of event) and its raw events are deleted. After 90 days the backend holds no random id, only the counts.

The record in your browser is yours to keep: it stays until you delete it.

Plate E · When a lab asks a model

The model route

Some labs send what you type or choose in them to a language model. The prompt is offered to these routes in order and goes no further than the first that answers. Each lab's model route control names the one in use. A prompt is never part of a usage event.

  1. Your own key, if you entered one in the model route control. The prompt and the key go from your browser to the address you entered. The key goes nowhere else and is kept in this browser's localStorage.
  2. The labs' own route. A Cloudflare Worker passes the prompt to Cloudflare Workers AI and returns the reply. The Worker stores and logs nothing: no prompt, no reply, no header. It hands the address of the request to Cloudflare's rate limiter, which counts requests per minute.
  3. The public route, text.pollinations.ai, when the labs' own route does not answer, for example once it has used its daily allowance. The prompt then goes to Pollinations, a third party with its own terms.
  4. Offline. The lab's own engine answers in your browser and nothing is sent.

On a copy of the site served from your own machine, a local Ollama model is tried first, and the prompt stays on that machine.

Plate F · Other servers a page talks to

Hosting, fonts and libraries

Each of these receives a request from your browser, with the address it comes from. None receives the Labs OS record.

Hosting
GitHub Pages serves the site's files.
Fonts
IBM Plex Mono and Fraunces load from Google Fonts (fonts.googleapis.com and fonts.gstatic.com).
Libraries
Icons and a few libraries load from cdnjs (Cloudflare) and jsDelivr.
Public data
Some labs read public data from its source when you open them, for example Hacker News through hn.algolia.com.

The labs set no cookie and load no advertising or analytics script.

Plate G · Your rights, and how to use them here

Four controls, all under Your data

Export
Export JSON saves every record this browser holds. The file includes your random id (meta.install). A browser cannot read events back from the backend, so to get a copy of what is stored under your id, send the id to the address on plate A.
Delete
Delete everything removes the record from this browser and erases this browser's events from the backend. It says whether the erase succeeded. If it could not reach the backend it keeps the id, so you can repeat it.
Erase
Erase what was sent removes this browser's events from the backend and keeps the record here.
Withdraw
Sharing, No thanks. Nothing more is sent. What was sent before stays until you erase it or until the 90 days pass.

If you think this site handles your data wrongly, write to the address on plate A. You can also complain to a data protection authority. In Spain that is the AEPD (aepd.es).
